# TyZip 常见问题

## 打开时提示「无法验证开发者」，怎么办？

这是 Gatekeeper 在拦没有公证的应用，不是文件损坏。

1. 在 Finder 里找到 `TyZip.app`，**右键 → 打开**，再在确认框里点「打开」。
2. 如果还是被拦，先去掉隔离属性再打开：

   ```bash
   xattr -dr com.apple.quarantine /Applications/TyZip.app
   ```

   路径换成你实际放 `TyZip.app` 的位置。

只需要做一次，之后正常双击即可。

## 为什么没有签名和公证？

TyZip 是自用 + 群内分享的项目，没有 Apple Developer 账号，也不做公证（notarization）。
打包时只做 ad-hoc 签名，所以拷到别的 Mac 上第一次会被 Gatekeeper 拦。
这是预期行为，不是打包出错；按上一题处理即可。

## RAR 为什么只能读，不能创建？

TyZip 用的是 7-Zip 引擎，7-Zip 只有 RAR 的**解压**实现（受 unRAR 限制），没有写 RAR 的代码。
所以 RAR 只能浏览、解压、测试；要生成 RAR 得用 WinRAR 之类的工具。
需要自己打包时，用 7z 或 zip 更合适。

## 打开 zip 文件名是乱码怎么办？

Windows 上生成的 zip 常用 GBK 存中文名，而 zip 头里没有「UTF-8」标志；TyZip 默认按界面语言猜（简体中文 → GB18030），多数情况直接就对。还乱的话：

1. 打开压缩包 → 查看 →「名称编码」，逐个试 GB18030、GBK、Big5、Shift-JIS，以及菜单里的 Windows-1251、Windows-1250 等其它代码页，名字会立即按所选编码重开。
2. 想把默认改掉：设置 →「ZIP 文件名编码」，之后打开的包都按它解。
3. 新建 zip 时同一个选项决定写入编码；给 Windows 用户传包选 GBK/GB18030，给自己或 Linux 用户选 UTF-8。

这个选择只影响文件名显示，不改压缩包内容；编辑一个旧编码的包时，TyZip 会保持它原来的名字编码，不会偷偷换成 UTF-8。

## 为什么 `.tar.gz` 修改要先解压？

`.tar.gz` 是两层：外层 gzip 只是单流压缩，里面才是 tar。
外层没有办法只替换其中一个成员，所以 TyZip 把内层 tar 以**只读**方式打开。
要修改就先把内容解压出来，改完重新压缩；或者用「转换」转成 7z/zip 这类可写格式再改。

## 嵌套压缩包为什么不能直接修改？

内层包是从外层包临时解出来的副本，真正的文件还在外层包里。
改这个临时副本不会写回外层，所以 TyZip 只允许浏览和解压。
要改就先把内层包解压到磁盘，单独修改，再添加回外层包（外层包本身要可更新）。

## 分卷包为什么不能更新？

分卷包由 `.001`、`.002`… 多个文件组成，索引和各卷的数据是对齐的。
只重写 `.001` 会让后面的卷全部错位，所以 TyZip 直接拒绝更新。
要改就先把分卷包解开，改完重新创建一个分卷包。

## Office / OpenDocument 文件双击，为什么是交给系统而不是浏览内容？

`.docx`、`.xlsx`、`.pptx`、`.odt` 这些本质上都是 zip 容器，但你的目标是编辑文档，不是看里面的 XML。
所以 TyZip 把它们当文档处理，双击交给系统默认程序。
想浏览内部结构时，右键 → **作为压缩包打开**，就能像普通压缩包一样查看和解压。

## 为什么打开后是文件管理器视图，不自动解压？

这是有意的：打开压缩包不等于解压，避免像「归档实用工具」那样在磁盘上留下解压结果。
浏览、预览、搜索都在包内完成；需要文件时再点「解压」，自己选目标文件夹。

## 文本和图片预览有大小上限吗？截断是什么意思？

有：

- 文本最多读取并显示 2 MB，超出部分不显示，末尾会标「… 预览已截断」。
- 图片上限 32 MB，超过会提示太大，不预览。

这样是为了避免一个超大文件把界面卡死。「截断」只是预览显示得少，文件本身和解压结果都完整。

## 二进制文件为什么拒绝预览？

文本查看器排版二进制内容没有意义，还可能因为超长行、控制字符卡住界面。
所以 TyZip 识别出二进制后直接显示「无法预览」，不硬当文本打开。

## 语言切换为什么要重启？

语言包在启动时加载，切换语言只写入设置，界面文字要等下次启动才换。
设置里也有提示「语言修改将在重新启动 TyZip 后生效」。

## Intel 机器上为什么不能运行 arm64 包？

arm64 包只能在 Apple Silicon 上跑，Intel 机器需要 x86_64 包；两个架构是分开打包的。
Apple Silicon 可以跑 arm64，一般也能通过 Rosetta 运行 x86_64 包。
不确定的话看包名里的架构，或「关于本机」里的芯片类型。

## 为什么没有 Qt / Linux / Windows 版？

TyZip 只做了 macOS 版，没有 Qt 版本。
Linux 和 Windows 的适配与打包都还没做，所以没有对应安装包。

## 有 SFX 创建或基准测试吗？

都没有。
能创建的格式是 7z、zip、tar、wim，以及单流 gzip、bzip2、xz；不支持生成自解压程序，也没有跑分功能。

## 从哪里下载？怎么确认版本？

目前没有公开下载页，拿到的是群里分享的 `dist/TyZip-<版本>-<架构>.zip`。
确认版本：

- 打开 TyZip → 应用菜单 → 关于 TyZip，会显示版本号。
- 仓库里的 `packaging/version.txt` 是版本号的源头，打包名也带这个版本。
- 仓库目前没有 `CHANGELOG.md`，改动记录看 git 提交历史。

## 怎么反馈问题？

TyZip 是自用 + 群内分享，没有公开的 issue tracker。在群里说，或直接找维护者。
附上这些信息最有用：

- TyZip 版本（关于 TyZip）和 macOS 版本
- 压缩包格式，以及是本地文件还是分卷/加密包
- 复现步骤，和界面上的报错原文
- 能提供样例压缩包更好（注意别带隐私内容）
