# PeaZip 压缩包管理能力差距（v2：不含文件管理器）

- 更新：2026-10-29（发布 0.3.0 收口：同步 arm64 交叉构建、2 MB 前缀预览、批量逐包冲突与票 20–27 后的单元/规模锚点；能力差距结论沿用 2026-10-28 的复核：转换、名称/内容搜索、批量、解压策略、注释、条目重命名、编辑回写、预设、Services 已落地，2026-10-27 的 v2 结构保留）
- 数据来源：`docs/research/peazip-scale.md`（PeaZip 11.4.0 实测）、`docs/research/tyzip-inventory.md`（TyZip 代码盘点）、TyZip `README.md`
- 工作量：粗估，一人、熟悉 TyZip 代码库、macOS 单平台，单位人周；不是排期承诺。

---

## 0. 结论

1. **按"压缩包管理器"口径，PeaZip 还需 TyZip 吸纳的功能约 15 项**：核心 2 项、可选 8 项；另有 5 项长尾（稀有格式/SFX/修复）可长期不做。2026-10-27 版列出的 12 项核心工作中，除完整 CLI 与任务日志外其余均已落地。
2. **剩余高价值部分约 3–4 人周（≈1 个月）；加上可选约 3–5 个月；连长尾格式/SFX/修复一起补完约 5–9 个月**。不是 v1 的 2–2.5 人年——被剔掉的文件管理器、文件工具、跨平台/i18n/发行占了很大一块。
3. **TyZip 的压缩包管理核心已完成约 90%**：打开/列举/测试/解压（全部/选中/单条）/创建/添加/删除/信息、7z/zip 加密与密码重试、分卷、双层/嵌套包、13 列、预览、过滤、压缩参数深度，加上转换/名称+内容搜索（后台、可取消）/批量/编辑回写/条目重命名/解压策略/注释/预设/Finder Services。剩余核心是**完整 CLI 与任务日志**。
4. PeaZip 的 16.2 万行代码不能直接折算成压缩包管理差距：它的主 GUI `peach.pas`（80,938 行）同时承担文件管理器、文件操作、视图、设置、Windows 集成和脚本引擎；**约 8.0× 的代码量里很大一部分与压缩包管理无关**。

## 1. 先划边界：什么算"压缩包管理"

| 算 | 不算 |
|---|---|
| 打开/浏览包内条目、虚拟目录树、排序/过滤/面包屑 | 磁盘文件管理：复制/移动/删除/新建文件夹/批量重命名 |
| 创建/添加/删除/更新条目、格式选择、压缩参数、分卷 | 文件工具：查重、安全删除/擦除、文件逐字节比较、拆分/合并原始文件 |
| 解压全部/选中/单条、解压策略/目的地/智能子文件夹 | 文件管理器 UI：书签/历史/最近/剪贴板/缩略图网格/大图标模式 |
| 测试/信息/校验、加密与密码、注释 | 十六进制查看器、文件管理器多标签（"打开多个压缩包"另算） |
| 包内搜索、转换、批量/队列、包内编辑回写/重命名 | 跨平台移植、便携模式、55 语言、安装包/发行/CDN |
| 压缩预设、任务日志、CLI/系统集成（压缩/解压） | Windows 专属集成（注册表右键/发送到/MSIX/Win11 ShellEx）、Linux DE 集成 |
| 归档内预览（TyZip 已有且更强） | 文件管理器自带的系统文件浏览/图标/关联设置（TyZip 已有等价） |

> 说明：PeaZip 把"文件管理器"和"归档管理器"做成了同一个界面，所以很多功能（重命名、复制、删除、查重、哈希）同时作用于磁盘和归档。**TyZip 只需要归档那一半**。

## 2. 逐项判定：还要吸纳什么

判定：`吸纳` = 符合压缩包管理器定位、建议做；`可选` = 有需求再做；`不吸纳` = 文件管理器/文件工具/产品层，与定位无关。
工作量按"接入 TyZip 现有架构"估算。

### 2.1 格式与引擎

| PeaZip 能力 | TyZip 现状 | 判定 | 工作量 |
|---|---|---|---|
| 可读 243 种扩展名（PAQ/LPAQ/ZPAQ、ARC/WRC、PEA、ACE、UPX、Brotli、QUAD/BALZ/BCM 等） | 60 个 7-Zip handler，RAR/ISO/DMG/WIM/CAB/APFS/HFS/EXT/NTFS 等已覆盖 | **可选（长尾）**：日常缺的主要是 `.br`、`.arc`、`.pea`、`.zpaq`；ACE/PAQ 极罕见 | 4–8 周（按 1–2 周/后端） |
| 可写 ~20 个格式族（br、zst、arc、pea、zpaq/paq、upx、split、sfx、quad/balz/bcm） | 7 种：7z、zip、tar、gzip、bzip2、xz、wim | **部分吸纳**：zstd/brotli 单文件创建有实际需求；ARC/PEA/ZPAQ 视用户群 | zstd/brotli 2–4 周；ARC/PEA 各 2–4 周 |
| 自解压 SFX 创建（7z/arc） | 无 | **可选（低）**：macOS 很少用 | 1–2 周 |
| 压缩包修复/恢复记录（ARC/RAR） | 无；7-Zip 侧也没有现成入口 | **可选（低）**：依赖后端；RAR 修复还需 unrar | 2–4 周 |
| 多后端架构（前端调 9 个 CLI） | 进程内单 7-Zip 引擎 | **不吸纳架构本身**；只按格式需要引入最小后端（如 zstd/br CLI） | — |
| RAR 创建（需本机 WinRAR） | 只读 | **不吸纳**：许可与依赖都不划算 | — |

### 2.6 不计入"功能"的产品层（不吸纳）

## 3. 汇总：还需要吸纳多少

| 分类 | 数量 | 估算 |
|---|---|---|
| **核心（建议做）** | **2 项 + 1 个接线**：完整 CLI 归档操作、任务日志/报告窗口、内容搜索 engine 接线（Services 与批量汇总已有；多包并行可算可选） | **约 3–5 人周 ≈ 1 个月** |
| **可选（按需求）** | 8 项：拖出解压、多标签/多窗口、zstd/brotli 写入、keyfile 2FA、哈希/校验、任务脚本导出、通知、从包内条目创建新包 | **约 10–17 人周 ≈ 2.5–4 个月** |
| **长尾（不建议现在做）** | 5 项：ARC/PEA/ZPAQ/PAQ/ACE/UPX 读写、SFX、修复/恢复记录、RAR 创建、PEA AEAD | **约 9–17 人周 ≈ 2–4 个月** |
| 已在 2026-10 前落地 | 转换、包内搜索（名称）、批量/队列、解压冲突策略、智能子文件夹、快捷目的地、解压后删源、注释读写、条目重命名、编辑回写、压缩预设、Finder Services | **0** |
| 文件管理器/文件工具/平台/发行 | ~20 项 | **0（不吸纳）** |

**结论：需要吸纳的约 15 项（核心 2 + 可选 8 + 长尾 5）。高价值部分约 1 个月，加上可选约 3.5–5 个月，全部含长尾约 5.5–9 个月。**

对比 v1：v1 的"功能面对齐约 2–2.5 人年"包含了文件管理器（批量重命名、磁盘复制/移动/删除、查重、安全删除、文件比较、缩略图、Hex、书签、文件管理器 tabs 等）、文件工具和 i18n/文档；按压缩包管理口径，**大约砍掉一半以上**。对比 2026-10-27 的 v2，则又因 12 项核心工作中 10 项落地而大幅收缩。

## 4. 建议的落地顺序

**已完成（截至 2026-10-28，无需再排期）**

1. 解压策略 + 智能子文件夹 + 快捷目的地 + 解压后删源
2. 转换 + 包内搜索
3. 批量/队列/多包（串行）+ 批量汇总
4. 包内条目右键菜单 + 重命名 + 编辑回写
5. 注释读写（zip 写、7z 读）+ 压缩预设 + 密码 Keychain 记忆
6. Finder Services

**剩余核心（约 1 个月）**

7. CLI 归档操作（2–3 周）
8. 任务日志/报告窗口（0.5–1 周）

**第二梯队（体验，约 0.5–1 个月）**

9. 多包并行、拖出解压、多标签

**第三梯队（按用户声音再决定）**

10. zstd/brotli 单文件创建（2–4 周）
11. 哈希/校验、keyfile 2FA（3–5 周）
12. 稀有格式（ARC/PEA/ZPAQ/PAQ/ACE）、SFX、修复（不建议主动做）

**盘点时列出的现有问题，现在都已修或已同步**：分卷 16/50 GB 映射、更新已分卷包、ZIP Latin-1 越界、条目右键菜单、README 快捷键/默认语言/图标缓存。

## 5. 一句话定位

TyZip 是**压缩包管理器**：核心是"打开/浏览/创建/解压/测试/格式/加密"，转换/搜索/批量/编辑回写/条目操作/解压策略/系统集成也已在 2026-10 前落地。PeaZip 的文件管理器、文件工具、跨平台和 55 语言不属于这个范围——**剩下的不是 40 个功能，而是 2 个核心 + 8 个可选 + 5 个长尾**。
